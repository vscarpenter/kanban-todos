5.1 · Standards Compliance

HighHigh confClaudeEffort: SmallS1.1 — Coverage thresholds far below standards target

vitest.config.ts:24-29

Thresholds: lines:37, functions:38, branches:35, statements:36. Comment in file says "Baseline thresholds as of initial compliance pass (raise over time toward 80%)" — that intent has not been actioned, and there is no ratchet to enforce it.

Recommendation: Step the thresholds up by 5 points per release until 80% is reached. Wire CI to fail on regression.

Effort: Small (config only); the harder work is writing the tests that justify each step.

MediumHigh confClaudeEffort: SmallS1.2 — No tasks/ spec workflow on disk

Standards require tasks/spec.md, tasks/todo.md, and tasks/lessons.md for non-trivial work. Repo has none. archive/ contains historical implementation notes but is not the same artifact.

Recommendation: Add a tasks/ directory with a stub todo.md and a lessons.md. Even an empty scaffold normalizes the workflow for future sessions.

MediumHigh confClaudeEffort: SmallS1.3 — No ADR directory

No docs/adr/. Several decisions in this codebase qualify (CSP policy in PR #43/#63; static-export over SSR; IndexedDB over remote storage; choice of @dnd-kit over react-beautiful-dnd; Inkwell adoption). PRs and commit messages carry the rationale, but it disperses over time.

Recommendation: Backfill 4–6 ADRs from existing PR descriptions; require new ADRs for any future hard-to-reverse choice.

5.2 · Test Quality & Coverage

HighHigh confClaudeEffort: MediumT2.1 — Coverage gap (37% floor) vs. 80% standard

vitest.config.ts · 34 test files for 169 source files

The test estate covers stores well (boardStore.test.ts 688 lines, taskStore.test.ts 503) and dialogs decently, but utility modules and many components lag. The branches threshold (35%) is the most exposed metric.

Recommendation: Prioritize closing branches in the four files Sonar already calls out for cognitive complexity (conflictResolution.ts, conflictMerge.ts, validation.ts, shareTask.ts) — each branch is a behavior worth testing anyway.

MediumHigh confClaudeEffort: SmallT2.2 — Largest test files exceed standards file-size guideline

src/lib/stores/__tests__/boardStore.test.ts 688 lines · taskStore.test.ts 503 · exportImport.test.ts 486

Standards say "Limit code files to ~350-400 lines. Split by responsibility." Test files are not exempt — when they grow this large, they often mix unit, integration, and edge-case suites.

Recommendation: Split each by behavior (e.g. boardStore.crud.test.ts, boardStore.import.test.ts, boardStore.archive.test.ts). Mirrors how the production code is already split (taskStore.crudActions.ts, taskStore.filters.ts, ...).

MediumMedium confSonarEffort: SmallT2.3 — Constant-truthy in test assertion

src/lib/utils/__tests__/cn.test.ts:11

Sonar S6638: "Unexpected constant truthiness on the left-hand side of a && expression." Two occurrences. The assertion's logic short-circuits on a hardcoded literal, which means the test passes whether or not the production code does what it claims.

Recommendation: Replace constant LHS with the actual value under test.

5.3 · Security & Supply Chain

CriticalHigh confBothEffort: SmallSC3.1 — Service worker accepts unverified postMessage

public/sw.js:34-38

Listener reacts to any cross-origin or compromised page that calls navigator.serviceWorker.controller.postMessage({type:'SKIP_WAITING'}). The action itself is benign, but the pattern violates Sonar S2819 and creates a precedent for less-benign handlers later.

Recommendation (small fix):

self.addEventListener('message', (event) => {
  if (!(event.source instanceof Client)) return;
  if (event.source.url && new URL(event.source.url).origin !== self.location.origin) return;
  if (event?.data?.type === 'SKIP_WAITING') self.skipWaiting();
});
MediumHigh confBothEffort: SmallSC3.2 — Regex hotspots in iosDetection.ts & security.ts

src/lib/utils/iosDetection.ts:58 · src/lib/utils/security.ts:88

Both flagged as S5852 super-linear backtracking risk. Real DoS surface is limited (UA-string in #1 is platform-bounded; security.ts input is bounded by INPUT_LIMITS max 1000 chars), but the regex shapes ([\d.]+.*Mobile.*Safari, <[^>]*>) are easy wins to tighten.

Recommendation: For iosDetection, anchor groups: /Version\/[\d.]+\sMobile\/\S+\sSafari/. For security.ts, the <[^>]*> form is fine in practice given the length cap — keep it but add a one-line comment justifying.

MediumHigh confClaudeEffort: SmallSC3.3 — No CI dependency-audit gate

Standards require npm audit/bun audit on every CI build, failing on high severity. Repo has the tools (bun available, lockfile pinned with --frozen-lockfile --ignore-scripts) but no scheduled audit step in the deploy script visible from the audit surface.

Recommendation: Add bun audit --audit-level=high as a step in the deploy script and/or a pre-commit hook.

LowHigh confSonarEffort: SmallSC3.4 — Dockerfile COPY . hotspot

Dockerfile:24

Sonar S6470. Mitigated already by the multi-stage pattern (only /app/out reaches the runner) and by --ignore-scripts. Worth confirming a .dockerignore file excludes node_modules, .git, secrets.

Recommendation: Confirm a tight .dockerignore; mark hotspot as Safe in Sonar with link to the dockerignore.

5.4 · Architecture & Layering

MediumHigh confClaudeEffort: MediumA4.1 — Conflict-resolution layer is a dispatcher with embedded business logic

src/lib/utils/conflictResolution.ts · conflictMerge.ts

The two files form a 600+ line dispatcher: a strategy enum ('skip'|'overwrite'|'merge'|'rename'|'generate_new_ids'|'ask_user') drives switch statements that mutate result arrays in place. The shape repeats verbatim for boards, tasks, and (lightly) settings.

Recommendation: Replace with a strategy table — const strategies: Record<Strategy, Resolver> = {...}. Each resolver returns a new array (no in-place index lookups). Drops cognitive complexity to ~8 per resolver and makes the boards/tasks/settings repetition into a single generic resolveCollectionConflicts<T>(...).

LowMedium confClaudeEffort: SmallA4.2 — Store split is good; minor coupling between filters and DB

src/lib/stores/taskStore.filters.ts imports src/lib/utils/database.ts directly

The store split (boardStore, taskStore, taskStore.filters, taskStore.crudActions, taskStore.import, settingsStore) is well-shaped. One small hairball: taskFiltering.ts:15 calls taskDB.getBoards() directly, mixing storage and filtering concerns.

Recommendation: Inject the board-list as a parameter so the function is pure. Test simplifies from "needs IndexedDB mock" to "passes a board array."

5.8 · Error Handling & Observability

MediumHigh confClaudeEffort: MediumE8.1 — Logger is structured but undertelemetered

src/lib/utils/logger.ts:39-90

Production logger emits JSON lines via console.error/warn/info. Good shape, but: there's no log aggregator on the receiving end (this is a static-export client app) and no event correlation ID across user actions. For a privacy-first client-only app this is partly intentional, but failure modes (sw update fail, IndexedDB quota exceeded) currently surface as toasts and disappear.

Recommendation: Pipe ERROR-level logs to an in-app "diagnostics" page (off by default, opt-in via debug mode setting) so users can copy a redacted error trace when reporting issues.

MediumMedium confClaudeEffort: SmallE8.2 — 45 console.* calls outside the logger

Most are in logger.ts itself (the sink) and a handful in stores (console.info, console.warn) — see taskFiltering.ts:25, taskFiltering.ts:29, taskFiltering.ts:111, taskFiltering.ts:128, conflictResolution.ts, etc.

Recommendation: Route everything through logger.*. Add an ESLint rule (no-console with allowlist for logger.ts) to enforce.
