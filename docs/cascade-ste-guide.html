SECTION 0

About this manual

Descriptive

This manual tells you what Cascade does and how it operates.

Section 1 gives a general description of the application. Section 2 gives the data that the application keeps. Section 3 gives the procedures that you use to operate the application. Section 4 describes the parts of the application and how they operate together. Section 5 gives the known limits.

The text of this manual follows the rules of ASD-STE100 Simplified Technical English (STE). STE is a controlled language for technical text. It has a dictionary of approved words and a set of rules for writers. Each approved word has only one meaning. The rules keep sentences short and clear.

Some words in this manual are not in the STE dictionary. These words are technical names and technical verbs for software. Appendix A gives these words. Appendix B gives the rules and how this manual uses them.

SECTION 1

General description

Descriptive

1.1Purpose

Cascade is a kanban task manager. It operates in a web browser. You use it to record tasks and to see the status of each task.

A board shows your tasks in three columns: To Do, In Progress, and Done. Each task is a card in one of these columns. When the status of a task changes, you move its card to a different column.

1.2Location of your data

Cascade keeps all of your data in your browser, on your device. It does not send your tasks, boards, or settings to a server. It does not use accounts.

A different browser or a different device does not show your data. To move your data, make an export file and import it in the other browser. Refer to procedures 3.12 and 3.13.

1.3Main functions

  • You can make more than one board. Each board has a name, a color, and an icon.
  • You can create, edit, move, share, and delete tasks.
  • You can give each task a priority, a due date, tags, and a progress value.
  • You can search the tasks on one board or on all boards.
  • You can archive a task and restore it later.
  • Cascade archives tasks in the Done column after a number of days that you set. You can also set this function to Never.
  • You can export your data to a JSON file and import the file again.
  • You can install Cascade as an application on your device.
  • Browser agents can read and change your tasks through WebMCP.
SECTION 2

Data that Cascade keeps

Descriptive

Cascade keeps three types of records: tasks, boards, and settings. The tables that follow give the fields of each record and their limits. When a text is longer than its limit, Cascade cuts the text to the limit.

TABLE 2-1. Fields of a task
FieldValues and limits

StatusTo Do, In Progress, or Done. The status sets the column of the card.

TagsMaximum 10 tags. Maximum 50 characters for each tag.
Progress0 to 100 percent. Cascade uses this value only for tasks in the In Progress column.

FieldValues and limits

Color and iconThe color dot and the icon in the list of boards.

Auto-archive1 day, 1 week, 1 month, 3 months, 1 year, or Never1 month (30 days)

If no board exists, Cascade makes a board with the name Work Tasks. This board has a blue color and a briefcase icon.

SECTION 3

Procedures

Procedural
Note

In these procedures, the sidebar is the panel on the left side of the board. The task options button is the button with three dots on a card.

3.1Open Cascade for the first time

  1. Open https://cascade.vinny.dev in your web browser.
  2. Read the About page. Cascade shows this page only on your first visit.
  3. Click Open Cascade.
Result

Cascade shows the board. On the first visit, Cascade makes the Work Tasks board.

3.2Make a board

  1. In the sidebar, click Add board (+) next to Boards.
  2. Type a name in the Board Name field.
  3. If necessary, type a description.
  4. Select an icon and a color.
  5. Click Create Board.

3.3Create a task

  1. Push the N key. As an alternative, push Ctrl+K (Windows and Linux) or Cmd+K (macOS).
  2. Type a title in the first field.
  3. If necessary, type a description.
  4. If necessary, select a priority.
  5. If necessary, set a due date.
  6. If necessary, type tags. Put a comma between two tags.
  7. Click Create Task.
Note

You can also click Add task (+) at the top of a column. Then the new task goes into that column.

3.4Move a task to a different column

To move a card with a mouse:

  1. Drag the card to the new column.

To move a card on a touch screen:

  1. Touch and hold the card for a short time.
  2. Move your finger to the new column.

To move a card with the menu:

  1. Click the task options button on the card.
  2. Select Move to Column.
  3. Select To Do, In Progress, or Done.
Note

When you drag a card into the Done column, Cascade shows confetti and a message. If Reduce motion is on, Cascade does not show the confetti.

3.5Edit a task

  1. Click the task options button on the card.
  2. Select Edit Task.
  3. Change the fields.
  4. Click Update Task.

3.6Move a task to a different board

  1. Click the task options button on the card.
  2. Select Move to Board.
  3. Select the destination board.
  4. Click Confirm Move.

3.7Share a task

To copy the text of a task:

  1. Click the task options button on the card.
  2. Select Share Task.
  3. Click the Copy Details tab.
  4. Find the Plain Text box or the Markdown box.
  5. Click the copy button in the upper right corner of that box.
Result

Cascade puts the task text on the clipboard. The icon on the copy button changes for a short time.

To send a task in an email:

  1. Click the task options button on the card.
  2. Select Share Task.
  3. Click the Email tab.
  4. If necessary, type an email address in the Recipient Email (optional) field.
  5. Click Open Email Client.
Result

Cascade opens your email application with the task text in a new message.

3.8Search for tasks

  1. Type one or more words in the search field at the top of the board.
  2. To search all boards, click Filter.
  3. Set Search all boards to on.
  4. To show only one status or one priority, select it in the Filter panel.
Result

Cascade shows the tasks that contain all of the words. It searches the title, the description, and the tags. Upper case and lower case letters are the same for the search.

3.9Archive a task and restore it

To archive a task:

  1. Click the task options button on the card.
  2. Select Archive.

To restore an archived task:

  1. In the sidebar, click Archive.
  2. Find the task. If necessary, type a word from its title in the search field.
  3. Click Restore task next to the task.
Result

The task goes back to its board and its column.

3.10Delete a task

CAUTION

Make sure that you select the correct task.

You cannot restore a task after you delete it.

  1. Click the task options button on the card.
  2. Select Delete.
  3. Click Delete Task.
Note

To delete an archived task, open the Archive dialog. Then click Delete permanently next to the task.

3.11Set the auto-archive time

  1. In the sidebar, click Settings.
  2. Find Auto-archive completed tasks after.
  3. Select a time: 1 day, 1 week, 1 month, 3 months, 1 year, or Never.
  4. Click Save.
Result

Cascade archives each task that stayed in the Done column for that time or longer. A message shows the number of tasks that Cascade archived. If you select Never, auto-archive does not operate. Section 4.6 gives more information.

3.12Export your data

  1. In the sidebar, click Export Data.
  2. Select the data to export: Tasks, Boards, and Settings.
  3. If necessary, select Include archived tasks and Include archived boards.
  4. Click Export Data.
Result

Your browser downloads a JSON file. Keep this file in a safe location. It is your backup copy.

3.13Import data

  1. In the sidebar, click Import Data.
  2. Select a JSON file that Cascade exported. The maximum file size is 10 MB.
  3. Examine the data in the preview.
  4. If Cascade shows conflicts, select an option for each type of conflict.
  5. Click Start Import.
Note

A conflict occurs when the file has a task or a board that is already in Cascade. Section 4.10 gives the conflict options.

3.14Reset the application

CAUTION

Export your data before you reset the application.

The reset deletes all boards, tasks, and settings in this browser. You cannot undo the reset.

  1. In the sidebar, click Settings.
  2. Click Advanced.
  3. In the Danger Zone area, click Reset Application.
  4. Click Continue to reset.
  5. Click Reset Everything.
Result

Cascade deletes its database, local storage, session storage, and cookies. Then it loads the page again.

3.15Use the keyboard shortcuts

TABLE 3-1. Keyboard shortcuts (on macOS, use Cmd in place of Ctrl)
KeysFunction
NCreate a task.
Ctrl+KCreate a task.
Ctrl+1 to 9Go to board 1 to board 9.
HShow the list of keyboard shortcuts.
F1Show the user guide.
Ctrl+,Open the settings.
Note

The shortcuts do not operate when the cursor is in a text field.

SECTION 4

How Cascade operates

Descriptive

4.1Main parts

Cascade has no server code. All parts of the application operate in the browser.

TABLE 4-1. Main parts of the application
PartFunction
Static filesNext.js makes HTML, JavaScript, and CSS files. A host sends these files to the browser.
React componentsShow the board, the sidebar, and the dialogs.
Task storeKeeps the tasks, the filters, and the search cache in memory.
Board storeKeeps the boards and the selected board in memory.
Settings storeKeeps the settings. Only this store writes the settings.
TaskDatabaseReads and writes the records in IndexedDB.
Service workerKeeps copies of the pages. If the device has no network connection, it gives the copy.
WebMCP toolsGive eight tools to browser agents.

4.2Start sequence

  1. The browser gets the static files from the host.
  2. The root layout starts the theme, the notification manager, the install message, the update monitor, and the toast messages.
  3. The home page reads a visit flag from local storage. If the flag is not there, the page goes to the About page.
  4. The board component starts the three stores at the same time.
  5. The task store opens the database and reads all tasks. It changes the dates from text back into Date objects.
  6. The board store reads the boards. If no board exists, it makes the Work Tasks board. Then it selects the board that you used last.
  7. The settings store reads the settings. It adds the default value for each field that is not there.
  8. When the three stores are ready, the board shows. Then Cascade registers the WebMCP tools and starts auto-archive.

4.3Path of one change

Each change to a task or a board goes through the same path. A change from a browser agent also goes through this path.

  1. You

    You click, drag, or type.

  2. Component

    The component calls a store action, for example addTask.

  3. Store action

    The action removes HTML from the text and cuts the text to the limits.

  4. TaskDatabase

    The database class writes the record to IndexedDB.

  5. Store

    The store changes its state, applies the filters again, and clears the search cache.

  6. React

    The components that use the changed state show the new data.

The store changes its state only after the database write is complete. This makes sure that the screen does not show data that the database did not save. If the write fails, the store records an error, and a toast message shows the error.

4.4Storage

Cascade uses one IndexedDB database with the name cascade-tasks. The database version is 1.

TABLE 4-2. Object stores
Object storeKeyIndexes
tasksidboardId, status, archivedAt, dueDate
boardsidisDefault, order
settingsidNone

An archived task stays in the tasks object store. Its archivedAt field has a date. The board does not show tasks that have this date.

If Cascade is open in more than one tab, a database upgrade in one tab can stop the other tabs. Cascade then tells you to close the other tabs.

4.5Search and filters

Cascade applies the filters in this sequence: board, status, priority, tags, date range, and text. The text search is last because it uses the most time.

Cascade keeps search results in a cache for 5 minutes. The cache holds a maximum of 50 results. Cascade does not keep a result with 1000 tasks or more. Each change to a task clears the cache.

A search on all boards does not show tasks on archived boards.

4.6Auto-archive

Cascade examines the tasks when the three stores are ready. It also examines them when you change the auto-archive setting. It selects a task if all of these conditions are true:

  • The task is in the Done column.
  • The task has no archive date.
  • The completion date is the same as the auto-archive time or older.

If the setting is Never, auto-archive does not operate. Cascade keeps this value as 0 days.

Some tasks from older data have no completion date. For these tasks, Cascade uses the date of the last change.

Cascade selects and archives the tasks in one database transaction. This transaction starts after all earlier database writes. Because of this, auto-archive does not write old data over a change that you made at the same time.

A message shows the number of archived tasks. If the write fails, Cascade does not change the tasks, and the board shows an error message.

4.7Drag and drop

The drag and drop function uses the @dnd-kit library. A mouse drag starts after the pointer moves 8 pixels. A touch drag starts after a delay of approximately 0.1 seconds. This delay lets you scroll the page with your finger.

4.8Notifications

The notification manager examines the tasks each 5 minutes. It sends a browser notification for each task that is due in one hour or less. It also sends a notification for each task that is late.

The manager does not send notifications for tasks in the Done column or for archived tasks. It sends a maximum of two notifications for each task: one when the task is due soon, and one when the task is late. You must turn on the Notifications setting and give the browser permission.

4.9Security

  • React shows all user text as text. It does not use user text as HTML.
  • The host sends Content Security Policy headers with each page.
  • Before Cascade saves a task or a board, it removes HTML tags and angle brackets from the text.
  • Cascade also removes characters that it does not accept, and it cuts the text to the limits in Section 2.
  • Cascade imports only .json files of 10 MB or less. It examines the structure of each file before the import.
  • Cascade does not import a file from a newer major version of the export format.

4.10Import conflicts

Before an import, Cascade compares the file with the data in the browser. It finds these conflicts:

  • A task or a board in the file has the same ID as a task or a board in Cascade.
  • A board in the file has the same name as a board in Cascade.
  • The file has a default board, and Cascade also has a default board.
  • A task in the file refers to a board that does not exist.

For each conflict, you can skip the item, overwrite the item, merge the data, or give the item a new ID. When two boards have the same name, Cascade can add "(Copy)" or "(Copy 2)" to the name of the imported board.

4.11Updates and offline use

The service worker sw.js gets each page from the network first. If the device has no network connection, it gives the copy from its cache.

When the host has a new version, a toast message tells you. The version indicator shows the version number, the build time, and the commit hash.

4.12Browser agents (WebMCP)

Cascade registers eight tools on document.modelContext. If that object is not there, Cascade uses navigator.modelContext. If these two objects are not there, Cascade writes one line to the console and operates as before.

TABLE 4-3. WebMCP tools
ToolFunction
cascade_list_boardsGives the list of boards.
cascade_get_boardGives one board.
cascade_list_tasksGives the list of tasks.
cascade_get_taskGives one task.
cascade_create_taskCreates a task.
cascade_update_taskChanges the fields of a task.
cascade_move_taskMoves a task to a different column or board.
cascade_delete_taskDeletes a task.

Each tool examines its input and then calls a store action. As a result, an agent change goes through the path in 4.3. The read tools tell the agent that the task text can come from an unknown source. The delete tool tells the agent that its result is permanent.

4.13Deployment

The build makes a static export in the out folder. The deploy script copies these files to an Amazon S3 bucket. Amazon CloudFront sends the files to the browsers.

The browser does not keep a cached copy of the HTML files. The browser keeps the other files for one year. Next.js gives the JavaScript and CSS files new names in each build. Because of this, the browser gets the new files after each deployment.

SECTION 5

Known limits

Descriptive
CAUTION

Export your data at regular intervals.

If you clear the data of your browser, you delete all of your tasks and boards.

  • Your data is in one browser only. Cascade does not copy it to other devices.
  • Auto-archive operates when Cascade starts and when you change the setting. If Cascade stays open for many days, reload the page to start auto-archive again.
  • Cascade shows the confetti only when you drag a card into the Done column. The Move to Column menu does not show it.
  • The code has a rate limit function for the search. No part of the application uses this function at this time.
