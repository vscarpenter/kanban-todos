A healthy local-first kanban app with a few concrete quality gates to tighten.

Cascade has a strong privacy-first architecture, a broad E2E suite, a clean production build, and no current audit findings. The main risks are type-check drift in a test fixture, coverage below the stated 80% floor, Chromium-only E2E configuration, npm/Bun tooling mismatch, and runtime warnings that should be cleaned before they hide real regressions.

Detailed Findings

Each finding includes severity, confidence, evidence, recommendation, and effort estimate.

1. Standards Compliance

High Standalone type-check is failing
Confidence: highsrc/lib/stores/__tests__/taskStore.import.test.ts:41,57 · .github/workflows/ci.yml:29-30

bun run tsc --noEmit --pretty false fails with four errors. The mocked export result returns runtime Task objects with Date fields where SerializedTask strings are expected, and returns an empty settings object where full Settings is required.

Recommendation: update both mocked return values to serialized task fixtures and a complete settings fixture. Keep the test asserting the same behavior, but make the mock match the exporter contract.

Effort: Small.

High Coverage policy does not meet the repository standard
Confidence: highcoding-standards.md:277-280 · vitest.config.ts:28-34

The standards set roughly 80% line coverage as a floor. The configured thresholds are lines: 37, branches: 35, functions: 38, and statements: 36. Actual coverage is higher than the floor but still materially below 80%.

Recommendation: ratchet thresholds to current-safe values first, for example lines/statements/functions 55 and branches 50, then raise by 5 points after each focused coverage pass.

Effort: Small for the config change, Medium for the tests that make future ratchets credible.

Medium ESLint relaxes explicit return types and only lints src/
Confidence: higheslint.config.mjs:11-13 · package.json:10 · coding-standards.md:233-239

The standards require typed function signatures, but ESLint disables @typescript-eslint/explicit-function-return-type. The lint script also targets only src/, leaving e2e/, configs, and scripts outside the normal lint path.

Recommendation: lint src e2e scripts *.config.* or add targeted overrides. Re-enable explicit return types at least for exported functions and shared utilities.

Effort: Small to Medium depending on how many existing functions need annotations.

2. Test Quality and Coverage

High High-risk import/search paths have thin unit coverage
Confidence: highcoverage/coverage-summary.json

Vitest passes 492 tests, but several important boundary files remain under-tested: taskStore.import.ts at 15.38% lines, taskFiltering.ts at 20.45%, conflictResolution.ts at 27.11%, and validation.ts at 36.55%.

Recommendation: add behavior tests for import conflict decisions, malformed payload validation, search cache invalidation, and cross-board filtering. These should be unit-level tests that complement the passing Playwright import/search flows.

Effort: Medium.

Medium E2E helpers are duplicated and still rely on brittle CSS selectors
Confidence: highe2e/task-crud.spec.ts:272-303 · e2e/import-export.spec.ts:284-310 · e2e/settings-management.spec.ts:294-321

Common helpers like boardItem and createTask are repeated across specs. Some assertions locate UI by implementation classes such as .task-card and .kanban-column, which increases churn when markup changes.

Recommendation: move common board/task helpers into e2e/helpers/ and prefer role/name selectors or stable test ids for domain surfaces that do not have accessible names.

Effort: Medium.

3. Security and Supply Chain

Strength No current audit or secret findings
Confidence: highbun audit --json · rg secret scan

bun audit --json returned an empty advisory object. A repository scan for common secret patterns found no committed credentials; the hits were documentation, sample task text, design-token comments, and lockfile package names.

Recommendation: keep this posture, and add an explicit audit gate to CI so this remains enforced rather than manually checked.

Effort: Small.

Low CI does not currently run an audit gate
Confidence: high.github/workflows/ci.yml:23-33 · coding-standards.md:250-254

The CI quality job installs, lints, type-checks, and runs coverage, but does not run bun audit. The standards require dependency scanning as part of the build.

Recommendation: add bun audit after install and fail on high-severity findings.

Effort: Small.

4. Architecture

Strength Store and persistence boundaries are coherent
Confidence: highsrc/lib/stores/* · src/lib/utils/database.ts · docs/adr/0001..0005

The architecture cleanly separates Zustand stores, IndexedDB persistence, import/export utilities, and presentation components. ADRs cover the major platform choices: IndexedDB, Zustand, static export, Tailwind/shadcn, and dnd-kit.

Recommendation: preserve this boundary. New remote storage, telemetry, or sync features should go through an ADR because they would change the local-only product model.

Effort: Ongoing governance.

Medium Search preference hydration writes before the database is ready
Confidence: highsrc/hooks/useSearchState.ts:40-45 · src/lib/stores/taskStore.filters.ts:166-174,374-385 · src/lib/utils/database.ts:178-180

Playwright repeatedly logged Failed to save search scope preference: Error: Database not initialized. The hook reads settings and calls setCrossBoardSearch, and that action immediately calls saveSearchScope, which reads settings from taskDB before initialization has completed.

Recommendation: split hydration from persistence. Add a non-persisting internal setter for settings hydration, or make saveSearchScope no-op until database initialization is complete.

Effort: Small.

5. Maintainability

Medium Several production files sit at or above the preferred size limit
Confidence: highcoding-standards.md:224-231 · wc -l source scan

The standards recommend roughly 350-400 lines per file. Current production hot spots are src/components/userGuide/guideSteps.tsx at 477 lines, src/components/ExportDialog.tsx at 409 lines, and src/components/TaskDialog.tsx at 408 lines.

Recommendation: split guide content by step group and extract form-state/panel sections from the dialogs. Keep the top-level components as orchestration shells.

Effort: Medium.

6. Dependencies

Medium npm-based tooling is brittle because package manager guidance conflicts
Confidence: highREADME.md:38-42 · CLAUDE.md:25-27 · package.json:86-100

README.md leads contributors to npm commands, while package.json pins bun@1.3.5 and CLAUDE.md says Bun is the package manager. During this review, npm-based package execution failed in this repo with Override without name: eslint-plugin-import/minimatch, caused by override keys that npm does not accept but Bun tolerates.

Recommendation: make Bun the explicit primary path everywhere, or make the override block npm-compatible and add a package lock. Avoid documenting npm as supported until it is actually supported.

Effort: Small.

Low Twelve dependencies have available updates
Confidence: highbun outdated

Major candidates: lucide-react 0.577.0 -> 1.16.0, @vitejs/plugin-react 5.2.0 -> 6.0.2, eslint 9.39.4 -> 10.4.0, and typescript 5.9.3 -> 6.0.3. Minor/patch candidates include date-fns, tailwind-merge, @playwright/test, type packages, coverage, baseline mapping, and Vitest.

Recommendation: handle major upgrades one at a time after CI is green; batch safe patch/minor bumps separately.

Effort: Medium across multiple small PRs.

7. Performance

Low Production build passes, but no runtime performance profile was captured
Confidence: mediumbun run build · next.config.ts:28-35

bun run build completed successfully after rerunning outside the sandbox. The config includes package import optimization and static export. This review did not run Lighthouse, browser tracing, or bundle analyzer.

Recommendation: add a periodic bun run build:analyze check or document current route bundle sizes before starting large UI refactors.

Effort: Small.

8. Error Handling and Observability

Medium Production logger output is likely stripped by removeConsole
Confidence: highsrc/lib/utils/logger.ts:50-61 · next.config.ts:33-36

The logger writes through console.error, console.warn, and console.info. Next config sets removeConsole to true in production, which can remove those calls from the production bundle.

Recommendation: either preserve error and warn with the granular removeConsole option, or treat the app as intentionally client-silent in production and update the logger comments accordingly.

Effort: Small.

Medium Playwright logs repeated Radix dialog accessibility warnings
Confidence: highsrc/components/CreateBoardDialog.tsx:4,75-78 · src/components/KeyboardShortcutsDialog.tsx:4,25-28 · src/components/UserGuideDialog.tsx:4,32-38 · src/components/ArchiveDialog.tsx:119-126

The browser console repeatedly reports missing Description or aria-describedby for DialogContent. Several dialogs import only DialogTitle and omit DialogDescription.

Recommendation: add concise DialogDescription nodes to every dialog content surface, or explicitly pass aria-describedby={undefined} only where a description would be inappropriate.

Effort: Small to Medium.

9. Documentation and Onboarding

Low README and CLAUDE docs have stale details
Confidence: highREADME.md:3,10,38-42,147-153 · CLAUDE.md:72-73,117-120,176-178

README.md still advertises version 5.2.0 while package.json is 5.2.1, leads with npm commands, and lists old store filenames. CLAUDE.md references files such as memoryOptimization.ts, deploymentValidator.ts, and versionManagement.ts that are not present in the current file tree.

Recommendation: do one docs sync pass after the package-manager decision. Keep file-tree examples generated or deliberately high-level to avoid recurring drift.

Effort: Small.

The project task notes still mention follow-ups such as an unused AccessibleInput file, but that source path is no longer present. Stale task memory can mislead future cleanup work.

Recommendation: sweep tasks/todo.md after this review and replace stale items with the current roadmap below.

11. Configuration and Type Safety

Medium CI type-check command exists, but package scripts do not expose it clearly
Confidence: high.github/workflows/ci.yml:29-30 · package.json:5-14 · tsconfig.json:31-42

The CI runs bun run tsc --noEmit, relying on Bun to resolve the tsc binary even though package.json has no typecheck script. Local contributors scanning scripts may miss the same check.

Recommendation: add "typecheck": "tsc --noEmit" and update CI to bun run typecheck. Then fix the current test-file errors.

Effort: Small.

12. E2E Health

Strength Full configured Playwright suite passes
Confidence: high/private/tmp/kanban-playwright-results.json · playwright-report/index.html

The required Playwright run completed with 217 passed, 0 failed, 0 skipped in 61.0 seconds on the configured Chromium project. Failure messages: none.

Recommendation: keep the current suite as the release smoke gate and extend the browser matrix before calling the E2E suite cross-browser.

Effort: Small for config; Medium if Firefox/WebKit reveal app or test assumptions.

Medium Firefox and WebKit are absent from the configured matrix
Confidence: highplaywright.config.ts:14-19

The config defines only { name: "chromium", use: Desktop Chrome }. The prompt requested pass/fail/skip counts per Chromium, Firefox, and WebKit; only Chromium can be reported because the other projects do not exist.

Recommendation: add firefox and webkit projects, then either include them in CI or add an explicit test:e2e:cross-browser script.

Effort: Small to Medium.

30 / 60 / 90 Day Roadmap

A sequence that unblocks quality gates first, then makes the suite more durable.

0-30 days

Unblock and stabilize

  • Fix taskStore.import.test.ts serialized fixture types.
  • Add typecheck and audit scripts, wire them into CI.
  • Raise coverage thresholds to a current-safe ratchet.
  • Add missing dialog descriptions.
  • Resolve npm vs Bun documentation and override compatibility.
30-60 days

Broaden confidence

  • Add Firefox and WebKit Playwright projects.
  • Extract shared E2E helpers and reduce CSS selector coupling.
  • Add unit tests for import conflicts, validation, and task filtering.
  • Split the largest dialog and guide files.
  • Fix search preference initialization so Playwright logs are clean.
60-90 days

Modernize deliberately

  • Process dependency updates in small PRs, especially major bumps.
  • Move coverage thresholds toward 70-75% after risk-focused tests land.
  • Run bundle analysis and record baseline route sizes.
  • Sweep stale docs and task notes after the architecture/test updates.
  • Decide the production logging policy and align removeConsole.
